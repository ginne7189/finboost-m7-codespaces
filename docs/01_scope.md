# 가상 송금 서비스의 요구사항

## 목표와 범위
가상 계좌 demo-a에서 demo-b로 원화 정수를 이동하고, 중복 요청과 오류에도 기록을 일관되게 유지합니다.
초기 잔액은 100000원과 20000원입니다. 사용자 화면은 별도 구현하지 않고 client.py로 HTTP 요청을 보냅니다.
실제 은행, 결제대행, 외부 웹훅, 운영용 원장 및 정산은 연결하지 않습니다.

## 성공 조건
- 새 키와 유효한 요청: 201, 잔액 이동, 거래와 이벤트 저장.
- 같은 키와 같은 본문: 200, 같은 거래번호, 추가 출금 없음.
- 같은 키와 다른 본문: 409, 신규 거래 없음.
- 잔액 부족: 422, 두 계좌 잔액 유지.
- 재시작: 같은 데이터 파일/볼륨이면 기존 결과 확인 가능.
- 후속 처리: 미처리 이벤트만 처리 표시. 외부 알림은 전송하지 않음.

## 제한
공통 학습 토큰은 계좌 소유자 권한을 검증하지 않습니다.
원화 정수만 취급하며 수수료, 환율, 소수 단위와 반올림은 구현하지 않습니다.
성능 목표, 실제 은행 처리, 운영 백업/복구, 가용성은 검증하지 않았습니다.
