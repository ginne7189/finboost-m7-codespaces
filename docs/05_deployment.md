# 실행, 배포와 운영의 경계

## 현재 실행
터미널 A에서 python app.py, B에서 python client.py health를 실행합니다.
app.py는 기본 127.0.0.1:8000, DB는 data/lab.db를 사용합니다.
LAB_TOKEN은 서버와 클라이언트가 공유하는 학습용 인증값입니다. 실제 비밀값을 저장소나 자료에 넣지 않습니다.

## Docker
Dockerfile은 Python3.12-slim에 app.py, client.py, worker.py를 넣습니다.
컨테이너는 내부8000, 호스트는 교안에서127.0.0.1:8001을 사용합니다.
/app/data에 이름 있는 볼륨을 연결하고 컨테이너를 교체한 뒤 같은 키의 응답과 잔액을 비교합니다.
이름 있는 볼륨은 같은 Docker 호스트에 남는 저장소이며, 호스트 장애에 대한 백업이나 다중 서버용 DB를 의미하지 않습니다.

## CI 예시
ci-example.yml은 현재 저장소 루트의 예시입니다. .github/workflows/test.yml에 배치하고
연결된 저장소에서 실행해야 실제 CI가 됩니다. 예시는 테스트와 이미지 빌드만 있고 CD는 없습니다.

## 추가 설계
외부에 서비스하려면 사용자별 인증/계좌 권한, HTTPS, 영속DB, 비밀값 저장, 로그 및 경보,
배포 후 대표 거래 검사, 데이터 구조 호환성과 롤백, 백업/복구가 필요합니다.
현재 교안을 운영용 서비스로 그대로 공개하지 않습니다.
infra/main.tf는 SQS 검토 예시이며 init/plan/apply는 실행하지 않았습니다.
